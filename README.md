# MAX Chat на GREEN-API

Тестовое задание на должность «Фронтенд разработчик React».

Веб-чат для отправки и получения текстовых сообщений в мессенджере **MAX**
через [GREEN-API](https://green-api.com/max). Внешний вид повторяет
[web.max.ru](https://web.max.ru/).

**Демо:** https://max-chat.193-168-49-200.sslip.io/

## Что умеет

1. Вход по учётным данным инстанса GREEN-API (`idInstance`, `apiTokenInstance`).
   Данные сразу проверяются через `getStateInstance`: при ошибке или
   неавторизованном инстансе показывается понятная причина.
2. Новый чат по номеру телефона получателя.
3. Отправка текста методом [SendMessage](https://green-api.com/v3/docs/api/sending/SendMessage/).
4. Получение ответов по [HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/):
   `ReceiveNotification` (long-poll на 20 с) → обработка → `DeleteNotification`.
5. История чатов хранится в `localStorage` браузера и переживает перезагрузку.
6. Адаптивная вёрстка: на телефоне список чатов и переписка — отдельные экраны.
   Светлая и тёмная тема по настройке системы.

## Запуск

Нужен Node.js 18+.

```bash
npm install
npm run dev        # http://localhost:5173
```

Сборка и тесты:

```bash
npm test           # юнит-тесты (vitest)
npm run build      # статическая сборка в dist/
```

Через Docker (сборка + nginx):

```bash
docker build -t max-chat .
docker run --rm -p 8080:80 max-chat   # http://localhost:8080
```

## Как проверить

1. Создайте инстанс MAX в [личном кабинете GREEN-API](https://console.green-api.com/)
   и авторизуйте его по QR-коду.
2. Откройте чат, введите `idInstance` и `apiTokenInstance`. Если в кабинете
   указан отдельный адрес API (вида `https://3100.api.green-api.com`), укажите
   его в блоке «Дополнительно».
3. Нажмите «+», введите номер получателя, напишите сообщение.
4. Ответьте с телефона получателя в MAX — ответ появится в чате.

## Устройство

```
src/
  api.ts               клиент GREEN-API: только нужные методы
  notifications.ts     разбор уведомлений в сообщения, нормализация номера
  useChats.ts          состояние чатов (reducer), цикл получения, отправка
  components/
    Login.tsx          вход и проверка инстанса
    Messenger.tsx      список чатов, создание чата
    ChatView.tsx       переписка и поле ввода
```

Бэкенд не нужен: GREEN-API отдаёт CORS-заголовки, поэтому браузер
обращается к API напрямую.

### Решения, которые стоит пояснить

- **Номер → chatId через `CheckAccount`.** В MAX ответ собеседника приходит
  с числовым `chatId` пользователя, а не с номером. Если писать на
  `79991234567@c.us`, ответ попадёт в отдельный чат. Поэтому при создании чата
  номер переводится в `chatId` методом
  [CheckAccount](https://green-api.com/v3/docs/api/service/CheckAccount/).
  Заодно пользователь сразу узнаёт, что на номере нет аккаунта MAX. Если метод
  недоступен, чат создаётся по номеру.
- **Каждое уведомление удаляется**, даже ненужное (статусы, медиа). Иначе
  очередь остановится на нём: `ReceiveNotification` будет отдавать его снова и снова.
- **Свои сообщения не дублируются.** Отправленное сообщение сразу появляется
  в чате, а когда из очереди приходит его эхо (`outgoingAPIMessageReceived`),
  дубль отсекается по `idMessage`, в любом порядке прихода. Сообщения,
  отправленные с телефона (`outgoingMessageReceived`), тоже видны в чате.
- **Сбой сети не роняет чат**: цикл получения показывает баннер
  «переподключаемся» и повторяет запрос через 3 с.

### Telegram и WhatsApp

Задание разрешает их как запасной вариант. Чат работает с инстансом любого
из трёх мессенджеров без настроек: пути методов у GREEN-API одинаковые.

- **Telegram** устроен как MAX: `CheckAccount` переводит номер в числовой
  `chatId`. Если у собеседника номер скрыт настройками приватности Telegram,
  метод ответит «аккаунта нет».
- **WhatsApp**: если `CheckAccount` недоступен, чат создаётся по номеру
  (`79991234567@c.us`). Для WhatsApp это и есть правильный `chatId`.

### Ограничения

- По заданию поддерживаются только текстовые сообщения (включая текст со
  ссылкой и цитатой). Медиа и прочие типы пропускаются.
- `apiTokenInstance` при включённой галочке «Запомнить» хранится в
  `localStorage`. Для учебного чата это приемлемо, в продакшене ключ нужно
  держать на сервере.
- Уведомления, пришедшие при закрытой вкладке, лежат в очереди GREEN-API
  24 часа и подтянутся при следующем открытии.
